# V3 方向：宠物动态化（呼吸 / 音乐律动 / 观众互动 / 战斗识别）

> 状态：方向备忘，未排期。记录 2026-11-28 讨论结论，避免以后重新论证。

## 目标

让守望先锋模式里的宠物从「静态贴图」变成「会呼吸、跟音乐、对观众和战斗有反应的活物」：

- 待机：呼吸、眨眼、尾巴摆
- 音乐：随节拍弹跳，换歌词时抖耳朵/张嘴
- 观众：礼物、上舰、点歌、切歌、弹幕指令触发动作
- 战斗：击杀、阵亡、受伤、大招就绪

## 数据来源（不碰游戏进程）

| 数据 | 方式 | 成本 |
|---|---|---|
| 音乐节拍 | 现有 `AudioPeak` 音频峰值 | 已有 |
| 礼物/上舰/点歌 | 现有弹幕流（`SEND_GIFT`、`GUARD_BUY`、点歌解析） | 已有 |
| 大招充能 | 屏幕采样大招圆环弧线（复用已对位的圆环坐标） | 低 |
| 击杀/阵亡/受伤 | 截取击杀播报区域 / 屏幕边缘，区域差分 + 模板匹配；**不做常驻 OCR** | 中 |
| 按键 | 不建议全局钩子（反作弊风险）；用「大招 % 突然归零」推断释放 | —— |

原则：只读屏幕像素 + 已有弹幕/音频数据；不注入、不读内存、不挂钩子。

## 动作清单

### 不需要新美术（程序动画）

呼吸、弹跳、整只倾斜、抖动、发光、爱心/金币/彩带粒子、文字气泡、点歌牌子。

### 需要分层（推荐）

每只宠物拆：身体 / 头 / 尾巴 / 左耳 / 右耳 / 眼睛(睁/闭) / 嘴 / 前爪×2，带支点 JSON：

- 摇尾巴、眨眼、抖耳朵、歪头、招手、张嘴跟唱、爱心眼/星星眼

### 需要序列帧（12fps）

扑击（击杀 8~12 帧）、阵亡趴下（6~8 帧）、伸懒腰（10~14 帧）、打哈欠、跳跃落地、舔毛、庆祝舞蹈。

### 事件映射

```
礼物   → 招爪 + 爱心眼 + 爱心粒子
上舰   → 庆祝舞 + 皇冠 + 彩带
点歌   → 歪头 + 「点歌：xxx — 观众」牌子
切歌   → 抖动
击杀   → 扑击
阵亡   → 装死
换歌词 → 抖耳 + 张嘴
音乐   → 随峰值弹跳
```

## 素材规格

- 每只 **512×512 透明 PNG**，底部中心为锚点，和圆环上沿接触点一致
- 分层命名 `body/tail/ear_l/ear_r/eye_open/eye_closed/mouth_open/paw_l/paw_r`
- 支点 JSON：`{x,y,pivotX,pivotY}`
- 序列帧：12fps、尺寸/基线一致、循环首尾无缝
- 体积：新增控制在 +3~5MB；放 `assets/themes/`，不嵌入 exe；直播姬 CEF 对新格式支持需实测（WebP 先测）

## 落地阶段

1. **阶段一（0 新美术）**：呼吸 + 音乐律动 + 礼物/上舰/点歌/切歌整只反应 + DOM 粒子/气泡/牌子
2. **阶段二（标坐标，0 新美术）**：`clip-path` 分区做尾巴摆/耳朵抖/眨眼
3. **阶段三（新美术）**：分层图 puppet（尾巴/耳朵/眼睛/前爪/头），Live2D 或 CSS 时间线
4. **阶段四（可选）**：击杀/阵亡识别（区域差分 + 模板匹配，不做 OCR）

## 外部工具参考

- 图像：Scenario.gg / Leonardo.ai（角色一致性）、SDXL + ComfyUI（ControlNet/IP-Adapter，上限最高）、Midjourney `--cref`
- 分层：Segment Anything / Layer Divider + Photopea/PS 手工修层
- 动画：Live2D Cubism（首选 2D puppet）、Spine（Web 运行时）、Rive（交互状态机）
- 不建议：AI 视频模型直接生成宠物动画（一致性/透明/循环都难）

## 与现有实现的关系

- 宠物渲染在守望先锋模式的 `/` 页面，圆环尺寸/位置已有对位设置（`OverlayRingSize` / `OverlayRingY`）
- 状态通过 `/lyrics/state`（OW）或 `/state` 轮询；一次性动作需要 nonce 触发
- 紧凑源模式（`?ow=compact`，900×320）已经做了圆环 1:1 拖拽对齐，后续宠物动画在同一坐标系内做即可
- 参考项目：`MapleOAO/xiaoyou-HUD`（Electron 透明 HUD，图层按 1920×1080 比例缩放；可借鉴其对圆环素材的摆放方式）
